- You no longer have scheduled automations refused because your checkout has uncommitted changes, or queued behind each other on the same repository. Every scheduled fire starts from a freshly fetched base branch in its own checkout, so several can run at once; an automation that resumes a saved chat still continues in that chat's checkout.
- You no longer have to open the pull request yourself, or trust an agent that opened one before anything was checked. When a runtime may open pull requests, a scheduled or webhook run whose checks pass is committed in conventional commits on a `<type>/<slug>` branch and opened as a pull request by Open Run.
- You no longer have to babysit that pull request. Open Run watches its CI, hands failing checks and merge conflicts back to the same conversation within the automation's repair attempts, and tells you in the run when it is green and mergeable. Merging stays with you.
- You no longer see `openrun schedule … open a pull request` ask the agent to ship unverified work; the CLI leaves shipping to Open Run and says so in the summary.
